# HAC 인원 관리 시스템

## 주소
- GitHub: https://github.com/2026-2-OSS/assign09-c01-22300161
- Vercel: https://assign09-c01-22300161.vercel.app
- MockAPI: https://6adea6fc4e88f1bba4a53b90.mockapi.io/Students

## 사이트의 정체?
HTML, Bootstrap CSS, JavaScript를 사용한 HAC 동아리 인원 관리 사이트입니다.
멤버 등록, 수정, 삭제 및 이름·별명 검색이 가능합니다.
검색은 이름 또는 별명을 전부 입력해야 합니다.

## 파일 설명
- index.html: 인원 관리 화면
- crud.html: 사용 방법
- app.js: 버튼 동작 및 서버 요청
- leb.html, array.html: 수업 시간 연습 파일

## 저장하는 정보
id, name, studentId, nickName, attendence, phone을 사용합니다.
id는 서버에서 붙이는 번호입니다.
학번·전화번호는 글자, 출석 횟수는 숫자로 저장합니다.
attendence는 기존 코드의 이름을 그대로 사용했습니다.

## 기능
- GET: 인원 목록 가져오기
- POST: 인원 등록
- PUT: 정보 수정
- DELETE: 확인 후 삭제

등록·수정·삭제 후 목록을 다시 가져옵니다.
데이터는 MockAPI에 저장합니다.

등록과 수정에서 이름, 학번, 출석 횟수를 확인합니다.
이름은 2글자 이상, 학번은 16~26으로 시작하는 8자리 숫자입니다.
출석 횟수는 비워 둘 수 없고 0, 1, 2처럼 입력합니다.
오류가 나면 알림을 띄웁니다. 수정 중에는 취소할 수 있습니다.

## 코드에서 알아둘 점
1. fetch()로 요청하고 async/await로 응답을 기다립니다.
2. response.ok로 성공 여부를 확인합니다. response.json()으로 데이터를 읽고 JSON.stringify()로 보낼 데이터를 바꿉니다.
3. 수정·삭제할 사람은 서버의 id로 구분합니다.

## 바꾼 점
배열에만 넣던 데이터를 MockAPI에 저장하도록 바꿨습니다.
부분 검색, 새로고침 버튼, setBusy(), showMessage()는 삭제했습니다.
검색은 filter()로 이름·별명이 같은 사람을 찾습니다.

## 문제 해결 및 느낀 점
코덱스를 사용하니 마치 내가 무빙워크에서 걷는 듯, 생산성이 향상되는 느낌을 받았고 이 기능을 어떻게 구현해야 할까에서, 무슨 기능을 넣어야 할까라고 생각하는 더 큰 범위에서 생각할 수 있는 기반이 되어 준 것 같다. 코덱스를 사용하면서 느낀 점이 있다. 13년 전 쯤에 도라에몽에서 영화를 컴퓨터(도라에몽의 도구)가 대신 만들어 준다는 에피소드가 있었다. 그 에피소드의 결말은 감독만 사람이고 나머지는 전부 컴퓨터가 만든다면 무슨 의미가 있는가? 라는 의미를 전한다. 그것은 그 감독이 그냥 컴퓨터한테 나는 버튼만 누를 테니 너가 알아서 멋진 영화를 만들라라고만 지시한 것에 초점을 맞춰서 비판한 것이 크다. 나는 그것은 게으름의 문제라고 생각한다. HOW는 언제나 아이디어(WHAT)을 저해하고 방해한다. 멋진 내용의 영화가 머릿 속에 떠올랐는데 언제 관련 지식을 처음부터 쌓아 올려야 한다면 결국 그것을 전부 쌓아 올렸을 때는 더 이상 아이디어는 물 건너 가고 없다. 중요한 것은 어떻게 구현하는 가가 아니라 무엇을 하려 하는가라고 생각한다. 코덱스를 사용하였지만 나는 버튼만 누를 테니 너가 알아서 과제를 해결하라고 하진 않았다. 코덱스가 자신 마음대로 하려는 것을 거의 실시간으로 통제하려 한 점에서 위 도라에몽의 내용과는 다른 점이 확실히 있다는 점을 강조하고 싶다.
물론 어떤 코드가 말썽를 일으키고 구현 가능하게 하는지 그 원리를 안다면 코덱스를 더 잘 다룰 수 있을 것이라는 사실에는 동의한다. 하지만 미래에는 과연 우리가 배우는 이 함수들이 과연 의미가 있을지 의문이 든다. 우리가 20세기 중반 공학자들처럼 기계어를 마는 사람이 누가 있는가? 이 또한 잊혀져 갈 것이다. 가끔 사람이 만든 것에는 손 맛이 있다고 말한다. 일본의 대부분의 사이트는 php라는 프로그래밍 언어로 만들어졌는데 굉장히 오랫동안 같은 방식으로 관리해왔다. 히즈넷 처럼 말이다. 정은 간다만 최근 php의 취약성이 AI에 의해 발견되면서 일본 굴지의 대기업 사이트들이 일시적으로 폐쇄되는 굴욕을 맛보았다. 미래로 나아가야 한다.
